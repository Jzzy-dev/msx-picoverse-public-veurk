# Change Log

## PicoVerse 2350 MSXUSBFDD v1.00

- First release: port of the PicoVerse 2040 MSXUSBFDD implementation (based on the MSXUSB USB FDD BIOS and Konamiman's Rookie Drive USB FDD BIOS / USBHOST NestorBIOS 2.2) to the PicoVerse 2350 (RP2350B).
- Aggregate `Makefile` with `msx`, `pico`, `tool`, `test` and `clean` targets (`msx/`, `pico/msxusbfdd/`, `tool/`, `tests/`).
- MSX BIOS (`msx/`): 32KB ROM (MSX-DOS 1 kernel in bank 0, USB FDD + `.DSK` driver in bank 1, Konami SCC mapper style 8KB banking at 5000h/7000h) assembled with `msx/tools/sjasm.exe` into `msx/dist/msxusbfdd.rom`. Includes `DSKIO`/`DSKCHG`/`GETDPB` (with the relative drive restoration fix in `GETDPB_IMPL`), `FORMAT`, `.DSK` boot menu, `CALL USB*` BASIC commands, `CAPS+ESC` panic abort, `Diag:`/`HW:` diagnostics, and optional `BOOT_SELFTEST`.
- Mailbox (`msx/src/pico_regs.asm`, `pico/msxusbfdd/mailbox.h`): memory-mapped registers at 7D00h-7FCFh of the cartridge slot (256-byte data window paged over an 8KB buffer, status, result, page, command, 16 argument bytes, 16 response bytes, `PVFD` signature).
- Firmware (`pico/msxusbfdd/`): adapted for the RP2350B (`PICO_BOARD=pimoroni_pga2350`, 48 GPIOs, `PIN_BUSSDIR=37`, `PIN_PSRAM=47`, QMI flash timing `0x40000202`, 210 MHz system clock, and open-drain `/WAIT` PIO responder via `set pindirs` in `msx_bus.pio` with input hysteresis on A0-A15 and D0-D7). Core 0 serves the MSX bus from SRAM; core 1 runs the TinyUSB host and mailbox commands (`usb_host.c`, `fs_service.c`, `diskio_usb.c`, FatFs R0.15).
- USB host (`pico/msxusbfdd/usb_host.c`): includes all UFI (CBI, CB, Bulk-Only) floppy and MSC flash drive features and hardware-validated fixes from the 2040 implementation — high-rate SRAM `epx` bulk/interrupt engine (`ufi_bulk_epx`), per-device `bMaxPacketSize0` tracking, 2-tier USB hub support (`CFG_TUH_HUB=2`), `SET_INTERFACE(0)` after `SET_CONFIGURATION`, bulk/interrupt stall routing, transfer abort, root-port bus reset, selective endpoint halt clearing, CBI interrupt draining after data-stage stalls, and hardware-level `Diag:`/`HW:` diagnostics.
- RP2350 & TEAC UF000x motor-spinup and `ENDPOINT_ERROR` stability fixes (`pico/msxusbfdd/msx_bus.pio`, `pico/msxusbfdd/msxusbfdd.c`, `pico/msxusbfdd/usb_host.c`):
  - Changed `msx_bus.pio` and `msx_pio_bus_init()` to drive `/WAIT` open-drain via `set pindirs, 1` / `set pindirs, 0 [1]` (releasing `PIN_WAIT` in `load_rom()`), matching `explorer.pio`, `multirom.pio`, and the 2040 implementation instead of driving `/WAIT` push-pull high.
  - Cleared RP2350's per-endpoint hardware 3-strike transaction/sequence error registers (`usb_hw->ep_rx_error`, `usb_hw->ep_tx_error`, and `USB_SIE_STATUS_ENDPOINT_ERROR_BITS` in `src/rp2350/hardware_regs/include/hardware/regs/usb.h`, which do not exist on RP2040 and are untouched by TinyUSB's `hcd_rp2040.c`) in `hw_diag_irq()`, `wait_for()`, and `ufi_bulk_epx()`, and added a 300 us poll-alive watchdog (`last_poll_us` via `USB_SIE_STATUS_NAK_REC_BITS`) in `ufi_bulk_epx()` with a 100 us `NAK_POLL` interval while waiting for the first packet (`total == 0`, during spindle motor spin-up and track seek) and 16 us once streaming (`total > 0`). When the TEAC UF000x turns its spindle motor on from standby (LED off), it briefly stops answering `IN` tokens (`> 3` `RX_TIMEOUT`s), which previously tripped `EP0_TRANSACTION` / `ENDPOINT_ERROR` on RP2350 and halted `epx` polling so the UF000x's FDC FIFO overflowed once the motor reached speed.
  - Restricted `ufi_clear_halts()` to bulk endpoints (`ep_in` and `ep_out`) so `ep_int` (`0x83`) data toggle is only cleared if `0x83` itself stalls.
- Tool (`tool/`): `msxusbfdd.exe` embeds the RP2350 firmware and the 32KB BIOS ROM and generates `msxusbfdd.uf2` with `RP2350_FAMILY_ID` (`0xE48BFF59`). Supports `-r` (external 32KB ROM) and `-o` (output filename).
- Tests (`tests/`): `make test` runs both the FatFs file service test (177 checks across FAT12/FAT16/FAT32 RAM disks) and the Z80 emulator test (101 checks against the real ROM and file service).
